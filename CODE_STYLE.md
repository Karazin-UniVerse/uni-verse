# UniVerse — Code Style & Guidelines

У цьому документі описані основні стандарти написання коду, правила найменування та архітектурні підходи проєкту **UniVerse**.

---

## 1. Правила найменування (Naming Conventions)

- **Змінні та функції**: `camelCase` (наприклад, `userName`, `getUserData()`).
- **Компоненти, Класи, Типи та Інтерфейси**: `PascalCase` (наприклад, `UserProfileCard`, `UserService`, `UserRole`).
- **Константи**: `UPPER_SNAKE_CASE` (наприклад, `MAX_AUTH_RETRIES`, `API_BASE_URL`).
- **Файли компонентів**: `PascalCase.tsx` або `kebab-case.ts` (дотримуватись однорідності у відповідному пакеті).

---

## 2. Гілки та коміти (Git Flow)

### Найменування гілок:
Використовуйте стандартні префікси:
- `feature/назва-фічі` — для нового функціоналу (наприклад, `feature/user-auth`).
- `bugfix/опис-багу` — для виправлення помилок (наприклад, `bugfix/header-alignment`).
- `hotfix/критичний-фікс` — для термінових правок у main.
- `chore/опис-задачі` — для оновлення залежностей чи конфігурацій.

### Повідомлення комітів (Conventional Commits):
Повідомлення повинні описувати **що** і **навіщо** було зроблено:
- `feat: додав авторизацію через Google SSO`
- `fix: виправив відображення таблиці в розкладі`
- `chore: оновив oxlint та конфігурації`
- `docs: додав опис кодстайлу`

---

## 3. Архітектура UI-компонентів (`packages/ui`)

Усі спільні UI-компоненти **обов'язково** розміщуються в пакеті `packages/ui` за такою структурою:

```text
packages/ui/src/components/
├── una/        # Дизайн-система (атомарні, базові примітиви)
└── complex/    # Складні, складені компоненти
```

### 1. `packages/ui/src/components/una/`
- **Призначення**: Базові елементи дизайн-системи (Primitives).
- **Приклади**: Кнопки (`Button`), інпути (`Input`), чекбокси (`Checkbox`), модалки (`Dialog`), бейджі (`Badge`).
- **Правило**: Не містять бізнес-логіки та запитів до API. Працюють виключно через props.

### 2. `packages/ui/src/components/complex/`
- **Призначення**: Комплексні, складені компоненти (Composites).
- **Приклади**: Таблиця оцінок, шапка профілю з аватаркою та випадаючим меню, блок завантаження лекцій, складні фільтри.
- **Правило**: Можуть комбінувати кілька компонентів із `una` та управляти складнішим UI-станом.

---

## 4. Лінтинг та перевірка коду

У проєкті налаштовано **OXLint** для миттєвої перевірки коду:
```bash
pnpm lint:ox
```
Перед створенням Pull Request переконайтеся, що `pnpm build` та `pnpm lint:ox` проходять без помилок.

# Bot that keeps third-party agent skills up to date

Not scheduled. This note says what is already known and what is still unverified.

**Goal:** a scheduled job that updates third-party skills in `.agents/skills/` and opens a pull request, so nobody has to do it by hand.

**Context**

- Third-party skills are listed in `skills-lock.json`: `source`, `skillPath` and a `computedHash` of the skill folder. There are no versions in it.
- `.agents/skills/` is canonical; `.claude/skills/` is a copy made by `scripts/sync-skills.mjs`, and `GEMINI.md` is generated by `scripts/sync-gemini-context.mjs`. The pre-commit hook runs both, so a bot PR would need to run them as well.
- The team has a Windows contributor, so avoid symlinks.

**Options to evaluate (none verified yet)**

- A scheduled GitHub Actions workflow that runs `npx skills update` (if our CLI version supports it), re-runs both sync scripts and opens a PR with a PR-creation action.
- Renovate or Dependabot: likely a poor fit because the lock has hashes, not versions.
- Microsoft APM (Agent Package Manager): copies skills into `.claude/skills/` and `.agents/skills/` from an `apm.yml` manifest. Open questions: whether it can update and open PRs on its own, how it pins versions, and the migration cost for 11 third-party skills.

**Decision needed:** which tool owns skill installation (`npx skills` today, APM as a candidate) before building any automation.

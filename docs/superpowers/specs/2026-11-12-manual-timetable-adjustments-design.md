# Технічний дизайн: Ручне коригування розкладу деканатом

**Дата:** 12 листопада 2026 р.  
**Статус:** Затверджено користувачем  
**Гілка:** `feature/timetable`

---

## 1. Мета та огляд

Забезпечити деканату можливість гнучкого ручного коригування навчального розкладу на двох рівнях:

1. **Коригування чернетки до публікації**: зміна дня тижня та пари для всієї дисципліни в обраному варіанті-кандидаті.
2. **Перенесення опублікованого заняття**: зміна конкретної календарної дати та пари для окремого заняття з обов'язковою перевіркою конфліктів у реальному часі.

### Ключова вимога валідації

Будь-яке ручне перенесення або зміна слота **зобов'язані перевіряти перетин як для студентських груп/потоків, так і для викладача** (якщо викладач призначений). Якщо новий слот створює накладання або порушує календарні обмеження, зміна відхиляється із зазначенням конкретного конфлікту.

---

## 2. Архітектура та перевірка конфліктів

Усі перевірки здійснюються за допомогою єдиного чистого валідатора `@universe/core`: `checkTimetableConflicts`:

- **Перетин студентів (`STUDENT_OVERLAP`)**: заняття не може перетинатися в часі з іншими заняттями тієї самої групи, її підгруп чи лекціями спільного потоку.
- **Перетин викладача (`TEACHER_OVERLAP`)**: призначений викладач не може одночасно вести дві пари на різних заняттях.
- **Обмеження суботи (`SATURDAY_RESTRICTION_VIOLATION`)**: заняття, дозволені лише по суботах, не можна перенести на будень, а буденні пари — на суботу без дозволеного відпрацювання.
- **Пізні пари**: 6-та та 7-ма пари дозволені лише за наявності дозволу `hasLateSlotAuthorization`.

## 3. Бекенд API

### 3.1. Зміна регулярного слота в чернетці

- **Маршрут**: `PATCH /timetable/versions/:versionId/slots`
- **Авторизація**: `ADMIN` / Деканат.
- **Тіло запиту (`AdjustDraftSlotDto`)**:
  ```ts
  export class AdjustDraftSlotDto {
    teachingAssignmentId: string;
    fromWeekday: number; // 1 (Пн) .. 6 (Сб)
    fromPair: number; // 1 .. 7
    toWeekday: number; // 1 (Пн) .. 6 (Сб)
    toPair: number; // 1 .. 7
  }
  ```
- **Логіка обробки**:
  1. Знайти всі події версії з заданим `teachingAssignmentId`, які припадають на `fromWeekday` та `fromPair`.
  2. Перерахувати дати цих подій на новий `toWeekday` у відповідних навчальних тижнях.
  3. Сформувати проекцію нового розкладу версії та запустити `checkTimetableConflicts`.
  4. Якщо знайдено жорсткі конфлікти (студентів або викладача) — транзакція скасовується, повертається `409 Conflict` з детальним масивом конфліктів (`hardConflicts`).
  5. Якщо розклад валідний — оновити записи `TimetableEvent` у БД, перерахувати штрафний бал версії та повернути оновлені події.

### 3.2. Разове перенесення опублікованої події

- **Маршрут**: `PATCH /timetable/events/:id/reschedule`
- **Авторизація**: `ADMIN` / Деканат.
- **Тіло запиту (`RescheduleEventDto`)**:
  ```ts
  export class RescheduleEventDto {
    newDate: string; // ISO date 'YYYY-MM-DD'
    newPair: number; // 1 .. 7
    reason?: string;
  }
  ```
- **Логіка обробки**:
  1. Завантажити існуючу подію `TimetableEvent` та всі інші активні події опублікованої версії на цільову дату `newDate`.
  2. Перевірити наявність конфліктів у студентів групи/потоку та викладача на парі `newPair`.
  3. При виявленні накладання — викинути `ConflictException` із зазначенням дисципліни, з якою стався конфлікт.
  4. При успіху оновити `date`, `pair`, `stableKey`, зберегти причину перенесення (якщо вказана).
  5. Оновлена подія автоматично відображається у веб-інтерфейсі та в iCal-підписці.

## 4. Інтерфейс користувача (Frontend)

### 4.1. Коригування чернетки у вікні перегляду (`TimetableManagement.tsx`)

- У таблиці тижневого розкладу обраного кандидата (`previewSlots`) на кожній картці заняття додається кнопка швидкої дії «Змінити слот».
- Відкривається модальне вікно **«Перенесення слота дисципліни»**:
  - Назва дисципліни, тип заняття, викладач, аудиторії/групи.
  - Поточний слот: День тижня, номер пари.
  - Вибір нового дня тижня (Пн–Пт або Сб для спеціальних дисциплін).
  - Вибір нової пари (1–7 пара).
- **Клієнтська валідація**:
  - Перевіряє зайнятість слота цільових студентських груп та викладача за іншими заняттями цього ж кандидата.
  - При виявленні накладання кнопка «Застосувати» вимикається, показується підказка з дисципліною-конфліктом.
- При успіху викликається `timetableApi.adjustDraftSlot`, кандидат оновлюється без перезавантаження сторінки.

### 4.2. Перенесення опублікованої пари у студентському/викладацькому розкладі (`ScheduleView.tsx`)

- Для користувачів з роллю `ADMIN` у картках занять (режими «День» та «Тиждень») додається пункт «Перенести пару».
- Модальне вікно перенесення:
  - Вибір нової дати в межах семестру (Date picker).
  - Вибір номера пари (1–7).
  - Поле введення причини перенесення.
- Помилки бекенду (наприклад, «Викладач або група КС12 вже зайняті на 2-й парі 15.09.2026») виводяться у вигляді тосту та банера в модалці.
